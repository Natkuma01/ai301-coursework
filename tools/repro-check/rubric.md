# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| `environment_matches` | Read the repro report's environment record against the issue context and repo-facts block, using the Environment section of `references/evidence-guide.md`. | Pass when the environment information is sufficient to understand what was tested and it matches the environment or versions targeted by the issue. If there is a relevant difference, pass when the difference is clearly identified so the result is not presented as if it came from the issue's exact environment. | required |
| `steps_followable` | Read the reproduction steps against the issue context, using the Steps section of `references/evidence-guide.md`. | Pass when another contributor could follow the described actions, commands, inputs, or configuration from a known starting state and perform the same reproduction attempt without having to guess a necessary step. The steps do not need to successfully trigger the bug when the reported outcome is an evidenced cannot-reproduce. | required |
| `behavior_matches_issue` | Read the repro report's artifacts, such as output excerpts, logs, error messages, screenshots, or test results, against the specific behavior described in the issue, using the Behavior shown section of `references/evidence-guide.md`. | Pass when the evidence tests the specific behavior described by the issue. A successful reproduction passes when the artifacts show that behavior. A cannot-reproduce also passes when the contributor made a valid attempt to trigger that same behavior and the artifacts clearly show the actual result, even though the reported bug did not occur. Fail when the attempt or evidence concerns a different or merely adjacent behavior. | required |
| `outcome_is_honest` | Compare the repro report's stated outcome and claims with its environment, steps, and artifacts, using the Honesty section of `references/evidence-guide.md`. | Pass when the stated conclusion says exactly what the evidence establishes and no more. A supported reproduction and an honestly evidenced cannot-reproduce can both pass. Fail when the report claims reproduction, non-reproduction, or a cause that its evidence does not establish. | required |
| `repo_conventions` | Read the claim comment and repro comment against the issue context, repo-facts block, contribution policy, templates, and any AI-use disclosure requirements, using the Comms section of `references/evidence-guide.md`. | Pass only when the comments identify the correct issue, accurately describe the contributor's own work, and satisfy the repository's stated communication requirements. If the repository requires disclosure of AI assistance for issue comments or other submitted communication, the required disclosure must be present and must satisfy the stated policy; missing a required disclosure fails this check. A claim made before reproduction must describe intended work rather than assert an unverified result. | required |

# Verdict rule

Accept the package only when every required check passes. Reject the package if any required check fails or is unclear. An unclear result counts as a failure because the package should not be posted until the missing evidence or information is resolved.
